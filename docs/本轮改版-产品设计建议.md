# 恒瑞 CMS 原型本轮改版：产品设计建议

> 评审日期：2026-11-24\
> 适用项目：hengrui-cms-prototype\
> 阶段：产品方案已落实为可运行原型，以下保留设计依据和边界。\
> 已确认：审计指操作审计，用于追踪谁修改了内容、标签、审批信息等。

## 0. 当前实现状态

本轮改版及后续确认的取消、重新匹配规则已接入现有原型：

- **操作审计**：独立菜单与只读权限，仅保留用户写入操作，按模块筛选；列表显示操作人、时间、操作、简短说明和结果，不展示字段差异或详情。
- **上传确认**：内容库新增“待归档”，上传批次和文件可恢复；解析完成后核对材料及页级标签、推荐和审批；逐份确认、批量归档；修改内容信息、素材或标签后重新确认。提交后源文件与审批信息固定，仅失败任务可重试。新版本仅归档时生效，冲突需重新核对。
- **标签相似**：手动新增、改名或分类调整、推荐采纳、待归档内容建标签和 Excel 导入统一检查；同分类精确重名阻断，相似候选仅供核对，用户可返回修改或确认继续入库。原型采用名称规范化及编辑距离，阈值 0.7，最多展示 5 个候选。
- **用户导入导出**：提供模板、校验预览、错误明细、整批创建和按筛选结果导出；保留工号前导零和现有角色保护规则。
- **取消操作**：支持单文件和整批取消尚未归档的内容；推荐按来源取消和恢复，已采纳绑定保留。取消项不再进入待办，后台返回不能恢复已取消文件。
- **标签重新匹配**：标签库集中维护后手动批量发起；仅补充新命中标签，全部已有绑定保留。复用待归档区域和现有确认页，直接展示完整材料、页级结果，逐份确认后统一更新，文件版本不变。
- **关联模块**：工作台待确认归档入口、按上传人投递通知、上传/确认/归档时间、新权限及历史迁移；多页面同步保存数据，提交前读取最新状态再校验。

沿用本地演示数据和模拟解析任务；正式研发需要接入文件解析及相似检索服务，并由服务端实现权限、并发控制和可靠审计存储。用户导入只创建账号，不通过文件修改已有账号；审计页不提供日志编辑、删除或导出。

启动：在项目目录运行 `npm run dev`，访问 `http://127.0.0.1:5180/`。默认超级管理员可查看所有新增入口。

验证详情见 [本轮改版-验收记录.md](./本轮改版-验收记录.md)。下文“当前原型实际情况”表为改版前基线，后续章节保留产品设计说明。

## 1. 需求目标与现状

本轮目标：让内容在正式归档前经过人工核对，减少重复标签，提高账号批量维护效率，并让核心操作可追溯。

目标用户包括内容上传和维护人员、标签维护人员、系统管理员，以及有操作审计查看权限的人员。

本方案以当前原型代码为依据。根目录已有的恒瑞二期需求和操作手册主要描述知识库、FAQ、会议等模块，与本原型的页面结构不同，不能直接作为本轮的页面现状。

| 模块 | 当前原型实际情况 | 本轮变化 |
| --- | --- | --- |
| 操作审计 | 已有审计数据结构，记录部分上传、内容编辑、审批、标签和导出操作；没有审计页面，部分关键入口没有留痕 | 新增查询页面，并补齐核心业务事件 |
| 上传归档 | 点击“上传并归档”后直接创建内容或版本，再在后台执行解析打标 | 先暂存并解析，人工确认结果后才正式归档 |
| 新版本 | 上传保存时立即切换当前版本 | 新版本确认归档后才切换当前版本 |
| 标签新增 | 同一分类下精确重名会阻断，没有相似提示；手动新增、推荐采纳、Excel 导入均可创建标签 | 各创建入口统一执行相似检索和确认 |
| 用户管理 | 单个创建、编辑、启停，字段为姓名、工号、角色；支持自建角色 | 在用户管理列表增加导入、导出和模板下载 |

## 2. 页面范围与整体流程

建议继续复用现有导航和页面，仅新增一个“操作审计”菜单，以及内容库中的“待归档”页签。

```text
工作台：增加“待确认归档”待办
内容库
  已归档：现有正式内容列表
  待归档：上传批次、解析进度、异常、结果确认入口
  新增内容 / 上传新版本
    上传内容 → 解析打标 → 确认打标 / 内容结果 → 归档完成
标签管理：新增 / 改名 / 推荐采纳 / 导入时增加相似检查
系统管理 → 用户管理：创建账号、导入用户、导出用户、下载模板
操作审计：按模块筛选用户写入操作的简表
```

其中“待归档”承接跨页面、跨刷新和后台处理任务；上传向导承接单次操作。二者读取同一批次和明细，避免离开上传页后找不到待确认内容。

## 3. 操作审计：用户写入操作简表

### 3.1 页面设计

使用独立菜单“操作审计”，放在导航靠后位置，便于单独授权。页面只保留筛选和列表。

| 区域 | 建议内容 |
| --- | --- |
| 筛选区 | 操作时间、操作人（姓名 / 工号）、所属模块、操作、关键词 |
| 默认规则 | 最近 7 天，按操作时间倒序；时间统一使用北京时间 |
| 列表字段 | 操作时间、操作人 / 工号、所属模块、操作、操作说明、结果 |
| 操作说明 | 简单展示内容编号、标签名、账号或批量数量，最多 70 个字符；不展示字段前后值和逐项明细 |

例如：`内容库 / 修改内容信息 / CMS-00018`、`标签管理 / 新增标签 / 疾病领域 / 非小细胞肺癌`、`系统管理 / 批量创建用户 / 20 个账号`。

### 3.2 本期记录什么

| 所属模块 | 用户写入操作 | 简短说明示例 |
| --- | --- | --- |
| 内容库 | 提交上传、保存确认结果、确认、归档、取消归档、确认并更新内容标签、修改内容及审批信息、修改内容标签、作废、重试失败任务 | CMS-00018、2 份内容、当前文件标题 |
| 发布管理 | 保存发布草稿、提交发布 | 2 份内容 |
| 标签管理 | 新增 / 编辑 / 启停标签、导入标签、采纳 / 取消 / 恢复推荐、手动发起或重试匹配 | 标签名称、标签库 |
| 系统管理 | 创建 / 修改 / 启停账号、创建 / 修改 / 删除角色、批量创建用户 | 姓名 / 工号、角色名称、20 个账号 |
| 公众号采集 | 当前仅查询，无用户写入操作；保留模块筛选项 | 暂无记录 |

发布管理沿用二期功能定位，记录用户的保存和提交，不记录模拟平台反馈。

以每次用户提交的写入接口为记录单位，提交一次记录一条。批量操作保留一条汇总，不按字段拆分。不记录查询、浏览、搜索、下载、导出、登录、退出、通知已读，以及系统解析、后台匹配结果、任务完成或轮询。用户主动发起 / 重试任务属于用户写入，自动完成任务不再追加记录。

### 3.3 必须一起补的规则

- 保存操作人 ID、姓名 / 工号快照、时间、所属模块、操作、简短说明及结果，不新增字段差异和详情展示。
- 内容标签归入“内容库”，标签库维护归入“标签管理”；账号和角色维护归入“系统管理”。“排除系统操作”指自动任务，用户在系统管理模块的修改仍然记录。
- 各用户写入入口显式声明日志；未声明的视图更新、自动任务不推断生成记录。
- 业务变更和成功日志一起保存；未保存成功不能显示成功日志。最终写入失败时保留失败结果，表单输入校验不单独记录。
- 审计权限只授予日志查看，不自动授予内容编辑、系统管理或审批截图查看权限。截图继续使用现有独立权限。
- 历史日志仅展示可识别的用户写入操作，自动任务和查询记录不进入列表；缺失工号和结果显示“未记录”，不补造历史信息。
- 本期页面只读，不提供日志编辑和删除；审计导出、长期留存策略可后续明确。

## 4. 上传：引入真正的待归档阶段

### 4.1 核心业务规则

**上传成功表示文件已保存，归档成功才表示成为正式内容。** 解析完成仅触发“待确认”，不能自动归档。

```text
上传内容（暂存）
  ↓
解析打标中 ──失败──→ 异常处理 → 重试
  ↓ 成功
待确认：预览内容、核对字段、校正标签
  ↓ 人工确认
已确认
  ↓ 归档时重新校验
已归档
```

“解析 / 打标状态”表示系统处理情况，“待确认 / 已确认 / 已归档”表示业务进度，应分别存储和展示，不能把现有“处理完成”“标签已完成”直接解释为人工已确认。

### 4.2 四步向导（确认交互已修订）

根据本次反馈，确认页使用“文件队列 + 当前文件工作区”：

- 队列可按全部、处理中、待确认、已确认筛选；每份文件显示独立状态，以及是否配置封面、缩略图和补充视频。
- 工作区分为“内容信息与素材”“打标结果”。前者集中查看标题、摘要、封面、缩略图及可播放视频；后者在内容预览旁核对材料标签或指定页标签，通过弹窗添加、新建标签。
- 内容信息使用明确的“编辑 → 保存”弹窗，不通过失焦隐式提交。确认当前文件后可直接查看下一份待确认文件；底部统一归档已确认项。
- 解析较长时可离开并返回，处理中只查看已上传信息；源文件不允许更换或下载核对，审批信息只展示上传时记录。已成功解析的文件不提供再次解析操作，失败任务可重试。
- 上传阶段每份文件可独立补充封面、缩略图、一个视频。视频是关联素材，与源文件独立保存；支持 MP4、WebM、MOV，本地存储后可播放核对；未上传时明确显示空态。


| 步骤 | 页面与操作 | 进入下一步的条件 |
| --- | --- | --- |
| 上传内容 | 保留文件 / 公开链接、标题、审批登记、封面、缩略图和补充视频；主按钮改为“开始解析打标” | 文件和链接有效，必填信息通过校验；批次和原文件暂存成功 |
| 解析打标 | 显示每份内容的进度和失败原因，可重试失败项；允许离开页面后回来继续 | 单份处理成功即可进入确认，不必等待整批 |
| 确认结果 | 左侧文件队列；右侧通过页签查看信息及素材、核对正文与标签；确认后可进入下一份 | 解析有效，必填信息完整，标签已核对；审批沿用现有校验 |
| 归档完成 | 展示成功、失败及仍待处理数量，提供查看内容、继续处理入口 | 仅归档本次选择且已确认的明细 |

底部按钮建议为“归档已确认的 N 份”。第一期支持逐份确认、批量归档即可，不要求逐页勾选，也不增加新的审核人或审批流。

### 4.3 确认页需要确认什么

- **内容结果**：标题、摘要、原文件 / 来源链接、页数和可预览内容；查看解析缺失或失败提示。本期不引入原文件正文编辑器。
- **材料标签**：整份材料的分类和标签；显示 AI 识别和人工补充来源，允许添加、删除或调整。
- **页级标签**：PDF、PPT、Word 按页定位，显示当前页标签及失败提示，避免只核对材料标签。
- **未匹配推荐**：可以选择已有标签、具备权限时创建新标签、取消推荐。取消不删除已绑定标签，可在当前文件恢复。
- **展示素材**：分别显示当前文件独立维护的封面、缩略图和补充视频，视频可直接播放。修改允许维护的内容信息及素材会取消原确认，但不触发整份文件重新解析。
- **审批结果**：只读查看上传时已完成登记的编号、有效期和截图名称；OCR 差异确认及“需要登记 / 不需要登记”只允许在提交上传前完成。

现有“确认上传信息”弹窗主要处理审批 OCR 差异，不能作为新增的内容和标签结果确认步骤。两类确认应使用不同文案。

### 4.4 校验与异常

| 场景 | 建议规则 |
| --- | --- |
| 整份解析失败或有页面解析失败 | 当前文件不能归档；仅提供失败重试，不允许更换源文件，不影响本批其他文件 |
| 解析成功但自动打标失败 | 可重试，或经人工完成标签校正后继续；不得把标签失败和文件解析失败混成一个不可恢复状态 |
| 没有匹配到适用标签 | 允许无标签直接确认并归档，不显示“已核对整份内容，无适用标签”勾选项 |
| 推荐标签尚未处理 | 不阻止确认或归档；推荐随正式内容版本及页码保留，可在详情或标签管理后续处理，不自动创建标签 |
| 新标签尚未入库 | 新标签创建执行相似检索；没有标签库维护权限时只能用已有标签或取消推荐 |
| 已确认后修改标题、摘要、展示素材或标签；失败任务重试 | 对应明细恢复待确认，其他明细保持原状态；结果确认绑定具体的一版处理结果 |
| 审批差异未确认、登记字段不完整、标签已停用 | 保留现有硬校验；归档前再次校验，提示修正受影响项 |
| 部分成功 | 成功项单独归档，失败项留在待归档；返回逐项结果，重试不能重复创建成功项 |
| 页面刷新或离开 | 已提交的批次和处理结果保留；从内容库“待归档”或工作台继续。尚未提交的本地输入仍可提示保存或放弃 |
| 归档失败 | 保留已确认结果；若业务数据未变化可直接重试，不要求重新上传或重新核对 |
| 权限被收回或原内容已作废 | 阻止继续确认 / 归档并说明原因，保留已经保存的批次和日志 |
| 重复点击归档 | 同一明细只能成功归档一次；已完成明细显示正式内容链接 |

### 4.5 新版本与重复上传

当前重复文件哈希或相同来源链接会被规划为已有内容的新版本，上传新版本也会立即切换 `current`。本轮至少需要调整以下行为：

1. 确认页明确提示“新增内容”或“将更新 CMS-xxxxx，预计生成新版本”，避免用户不知情覆盖当前版本。
2. 待归档新版本独立暂存，旧版本继续作为正式当前版本；确认归档时才生成正式版本并切换。
3. 归档前校验目标内容是否已有其他新版本；发现变化时提示重新核对，不覆盖他人刚归档的版本。预计版本号不能作为已锁定的正式编号。
4. 批次内完全相同文件建议提示移除重复项；与库内相同文件至少显示命中对象，不静默连续创建多个版本。更深入的查重策略可另行确定。
5. 新版本审批使用本次登记的快照，历史版本和已提交发布记录保留各自快照。

### 4.6 取消归档

- 范围：解析中、待确认、已确认未归档和归档失败文件；上传人及超级管理员需要仍具备上传权限。
- 入口：批次列表和确认页顶部提供“取消剩余归档”，当前文件底部提供“取消归档”。二次确认说明数量及“再次入库需重新上传”。
- 单份或批量取消仅处理尚未结束的文件；已归档文件、同批其他文件和已有正式版本保留。
- 取消后记录取消人、时间，明细只读，不计入待办、异常待处理、已确认或可归档数量；不删除标签字典、原文件或共享素材。
- 后台处理回调不能写回已取消明细，也不能重新产生其待办；重复取消不重复改变结果。
- 全部明细均归档或取消后，批次结束；通过“包含已结束批次”查看。

## 5. 新增标签：相似提醒覆盖所有入库入口

### 5.1 交互流程

```text
填写名称和分类
  → 精确重名校验
  → 相似检索
     无命中：保存
     有命中：展示只读相似候选 → 返回修改 / 仍然创建
```

建议在现有新增弹窗内增加“相似标签”结果区。输入时可提前提示，点击保存时必须基于最终名称和分类检查一次，避免改名后复用旧结果。

候选展示名称、分类、启停状态、相似原因，默认展示最多 5 个相关结果。候选不可选择，不提供“使用已有标签”操作；用户核对后决定是否仍然创建新标签。

### 5.2 硬阻断与软提醒

| 情况 | 处理方式 |
| --- | --- |
| 同一分类下精确重名 | 硬阻断，沿用现有规则；不能通过“仍然创建”绕过 |
| 同一分类下名称接近或可能同义 | 软提醒，用户返回修改或明确选择仍然创建 |
| 不同分类下同名 / 相似 | 展示分类差异，供用户核对是否仍要创建 |
| 相似标签已停用 | 展示停用状态，仅供核对 |
| 检索失败 | 保留输入，提示检索未完成并允许重试；不能把失败显示成“没有相似标签” |
| 用户调整名称或分类 | 旧检索及“仍然创建”确认失效，重新检查 |
| 提交前标签库发生变化 | 再校验精确重名及新命中候选；需要时重新提示 |

精确名称建议统一首尾空格、大小写和全半角；药物剂量、疾病分期、符号差异不能直接删掉后判断为同一标签。相似检索覆盖所有二级标签，以同分类候选优先；新增一级分类时仅比较已有一级分类。

相似提示不执行标签绑定或映射。内容页原有的“添加已有标签”和推荐中的“选择已有标签”保持独立；选择新建后命中相似项，仍只提供返回修改和确认创建。

### 5.3 关联入口

- 手动新增标签：完整执行检索和确认。
- 编辑名称或所属分类：排除标签自身后执行检查；仅启停或改变展示开关无需重复检索。
- 推荐标签“采纳并添加”：名称已精确入库且可用时直接添加；需要创建时先检索，确认后创建独立的新标签并绑定到原推荐来源位置。
- Excel 导入：在现有预览中增加相似候选和处理选择，同时检查与现有库、同批其他新增标签的相似性；不能导入后才提醒。第一期可提供“仍然新增 / 跳过该行”，有未处理相似项时不提交。

用户选择“仍然创建”后生成正常的新增标签记录，说明保留标签名称即可，不展开候选明细，不增加审批或必填理由。相似阈值和医学同义识别能力需要用真实标签样本校准，原型可先用可评审样例表现交互。

### 5.4 推荐标签取消与恢复

- 待归档确认页的推荐可按需采纳、取消，或留待归档后处理；不作为确认或归档的前置条件。“已取消的推荐”中可恢复。
- 正式内容推荐的每个来源行同样支持取消、恢复；材料与页级来源独立处理，旧版本只读。
- 标签管理推荐详情可取消该条推荐的全部待处理来源，确认弹窗说明已采纳绑定保留；已取消来源仍可查看和恢复。
- 不删除标签库标签，不撤销已采纳绑定，不自动取消其他文件的新来源。本轮不增加“撤销已采纳”。
- 相同文件版本、位置、名称和分类的人工取消或移除会被记住，下次重跑或重新启用不自动补回；名称或分类变化时按新定义重新识别。

### 5.5 同步最新标签到文件：定义、范围与生效

**定义**：维护完一批标签后，由用户在标签管理点击“同步最新标签到文件”，手动发起一次批量任务。保存单个标签不自动触发或弹出历史文件匹配提示。任务使用启动时的启用标签库，复用已有解析内容，仅对尚未绑定的材料、页级位置补充匹配。全部已有绑定保留，结果页展示“已有标签＋本次补充标签”的完整结果。

| 项目 | 规则 |
| --- | --- |
| 发起权限 | 维护标签库与内容标签两项权限；标签库与内容库菜单可用 |
| 文件范围 | 默认“选择部分文件”，也可切换“全部文件”；仅正常、解析完成且页面解析完整的正式内容当前版本 |
| 不参与范围 | 待归档上传文件、历史版本、作废或取消文件、解析未完成文件 |
| 标签范围 | 已启用且所属分类启用的标签参与匹配；不要求逐个选择新增标签 |
| 处理位置 | 材料和具体页码分别计算，同一标签在不同页独立绑定 |
| 计算时 | 仅写入“标签更新”批次，不修改正式文件；本地原型模拟后台处理，离开或刷新可恢复 |
| 生效时 | 逐份确认后，点击“更新已确认的 N 份”，仅将最终标签结果保存到原文件当前版本 |
| 影响范围 | 更新标签、人工排除记录及内容更新时间；保持已归档、不生成文件新版本、不改源文件、审批、封面、缩略图及视频，不自动重新发布 |
| 并发任务 | 同一时间仅保留一批未结束的标签更新任务；再次点击入口继续已有批次，结束或取消后可重新发起 |

### 5.6 标签变化场景结论

以下描述本次结果页中的完整结果，确认更新前正式内容继续使用原结果。

| 场景 | 本次结果 |
| --- | --- |
| 新增已启用标签 | 命中的文件或页面增加该标签，不命中不添加 |
| 新增停用标签 | 不参与匹配，不增加到文件 |
| 文件已有标签 | 不重新计算是否命中，保留自动和人工绑定；同一作用位置不重复添加，其他未绑定位置仍可匹配 |
| 原有标签被停用 | 已有自动和人工绑定保留，标记“已停用”；不产生新绑定 |
| 一级分类被停用 | 该分类下标签不参与匹配，已有绑定保留 |
| 标签重新启用 | 所属分类也启用时，下次用户主动批量同步才恢复参与匹配；已有绑定保留，仅补充未绑定位置；人工取消不因启用失效 |
| 标签名称修改 | 已有绑定按标签 ID 保留，显示新名称；未绑定位置按新名称匹配。不判断含义变化，不自动清理已有绑定 |
| 标签所属分类修改 | 已有绑定按标签 ID 保留并按新分类展示；新分类启用时，未绑定位置继续参与匹配 |
| 原有自动标签本次未命中 | 仍保留已有绑定，不自动移除；用户可在结果页手动维护 |
| 仅修改对外展示开关 | 标签绑定不变，展示设置生效，无需专门重跑 |

“停用”控制后续是否可新增使用，“解绑”由文件标签维护决定，对外展示由已有展示开关及发布快照控制。自动匹配仅补充，不自动解绑；材料和各页按“文件版本＋标签 ID＋作用位置”分别去重。已有自动、人工和停用绑定全部保留，用户明确移除或取消的结果不因再次匹配或重新启用而自动补回；整份文件曾经确认归档，也不把全部 AI 标签永久转成人工标签。

### 5.7 复用确认页的交互

```text
标签管理 → 同步最新标签到文件
  → 搜索 / 筛选 → 勾选文件（支持跨页）→ 确认同步 N 份
  → 后台匹配
  → 待归档区域的“标签更新”批次
  → 左侧文件队列 / 右侧预览与完整材料、页级标签
  → 可直接增删标签 → 确认本文件并查看下一份
  → 更新已确认的 N 份
```

- 与上传批次共用批次列表、搜索、类型筛选、文件队列、预览、素材查看、标签选择、逐份确认和底部提交栏。
- 用“上传归档 / 标签更新”区分任务类型；更新任务默认打开“打标结果”，只维护标签，其他信息只读。
- 直接给出最终完整结果，不增加拟增删建议、人工需核对状态、失败或跳过数量看板。
- 沿用处理中、待确认、已确认、已更新、已取消等文件状态；单文件异常在该文件就地提示及重试，不能确认为空结果。
- 原有停用绑定允许保留并确认；不能新增停用标签。此模式不套用新上传文件的停用标签归档阻断。
- 无标签可直接确认；推荐标签可稍后处理，不阻止确认、归档或更新。未处理推荐归档后按正式内容、版本及页码保留。修改已确认结果会取消该份确认，其他文件不受影响。
- 批次顶部可取消剩余更新，文件底部可取消本次更新，二次确认；尚未更新的正式标签保留，已更新项不回滚。
- 使用当前已有组件和枚举扩展，避免新增差异审批、标签更新版本、语义判断、逐标签任务和独立的结果看板。

**同步范围弹窗**：

- 入口和标题统一使用“同步最新标签到文件”；默认“选择部分文件”，不默认执行全库。
- 部分文件通过列表选择：支持标题 / CMS 编号搜索、格式与来源筛选、分页、逐行勾选、本页全选、跨页保留、仅看已选及清空选择。
- 搜索、筛选和翻页仅改变列表，不改变已选范围；筛选出文件不等于选择，不能凭输入框直接确定执行范围。
- 底部明确显示“已选 N 份文件”和“确认同步 N 份”，未勾选时不可执行；全部模式明确显示全量文件数量。
- 所选文件提交前已失效时阻止发起，提示重新选择，不静默缩小范围或扩大到其他文件。
- 弹窗仅保留两句说明：“执行耗时随文件数量和页数增加，算力消耗较大，请谨慎选择范围。”“后台执行，可稍后查看；结果确认后生效。”
- 原型没有真实服务的耗时数据，不展示虚构的分钟数。正式研发如有预估接口，可按文件数、页数和队列返回预计时长；不增加强制勾选或额外确认弹窗。

### 5.8 异常、冲突与历史兼容

- 发起时固定标签定义及文件版本；计算、确认和最终保存再次校验。名称、分类、启停变化或文件内容、绑定、新版本变化时，旧结果不可覆盖新状态，提示重新匹配该文件。
- 仅调整对外展示开关不影响匹配结果有效性。
- 失败文件保留正式结果，可单独重试；成功文件继续确认，不要求整批重跑。结果过期后的重试会重新读取当前文件和标签库，并清除原确认。
- 因取消而停止的任务，其后续返回结果不得写回；刷新后继续使用保存的批次及状态。
- 文件绑定保留名称、分类依据，标签改名前保存现有名称记录；尚未确认的本次结果不替换旧正式标签。历史已有记录缺少快照时不能补造其过去名称。
- 原型旧版直接写入的匹配任务不按新规则自动回放，需重新手动发起。
- 审计仅记录发起、重试、取消、确认和更新等用户写操作；说明使用“更新 N 份内容的标签”，不记录后台轮询和任务完成。

## 6. 用户导入导出：放在用户管理列表

“导入导出”建议作为“系统管理 → 用户管理”的批量操作，与“创建账号”并列，而非放进单个创建账号弹窗。

### 6.1 用户导入

第一期定位为“批量创建账号”，使用 `.xlsx`，复用现有工号登录体系和自建角色。暂不通过导入修改、停用已有账号。

```text
下载模板 → 填写 → 上传文件 → 校验预览 → 确认导入 → 结果汇总
```

| 字段 | 必填与规则 |
| --- | --- |
| 姓名 | 必填，去除首尾空格 |
| 工号 | 必填，按文本读取和写入，保留前导 0；沿用去空格、转大写后的唯一性及现有格式校验 |
| 角色名称 | 必填，匹配已存在的自建角色；不存在时报错，不自动创建角色 |
| 账号状态 | 不作为本期导入字段；与单个创建一致，默认启用 |

模板建议附可分配角色的参考工作表，排除系统保留的超级管理员角色。

校验预览展示行号、姓名、工号、角色、校验结果和错误原因。需检查同文件重复工号、系统内重复工号（包括停用账号）、角色不存在、必填缺失和格式错误。超级管理员账号和角色继续受现有规则保护。

为贴合当前标签导入的行为，建议第一期采用：**存在错误时整批不提交，支持下载错误明细，修正后重传；全部通过后统一创建。** 重传同一批次不能重复创建已成功账号；最终提交时重新校验工号、角色和当前权限。

导入成功展示实际创建数量和批次结果，并生成一条审计汇总，如“批量创建用户 / 20 个账号”。

### 6.2 用户导出

- 导出字段：姓名、工号、角色、启用状态、创建时间。
- 默认导出当前搜索 / 筛选结果的全部行，明确“共 N 个账号”，不能只导出当前页；有需要可在导出范围中切换为全部用户。
- 工号列强制为文本，保留如 `000023` 的格式。
- 权限沿用用户管理权限。本期不使用现有“下载与导出内容”权限来授权用户信息导出。
- 不导出密码、登录令牌等身份验证数据，也不新增当前模型没有的手机号、邮箱等必填字段。
- 导出属于查询，不写入操作审计。用户导出表不能默认解释为可批量更新账号的文件。

## 8. 原型改版范围与待确认项

### 8.1 建议本期做到的可评审结果

1. 一条完整链路：批量上传 → 后台解析 → 返回待归档 → 核对材料和页级标签 → 归档部分成功项 → 新版本正式生效 → 在审计中看到变更。
2. 三种标签结果：精确重名阻断、相似提示后返回修改、确认仍然创建；手动、推荐、导入入口规则一致。
3. 一条账号批量维护链路：下载模板 → 校验错误 → 修正 → 批量创建 → 导出当前结果；审计只记录批量创建。
4. 标签集中维护 → 同步最新标签到文件 → 完整结果逐份确认 → 更新已确认项；覆盖已有绑定全部保留、仅补充新命中、启停与分类约束、人工排除、取消和冲突。
5. 审计页能回答“谁，在什么时候，在哪个模块，执行了什么写入操作”；说明简短，不展示字段差异。

### 8.2 建议默认采用、但仍可调整的业务选择

- 结果确认由上传者完成，不新增独立审核角色。
- 归档按单份内容生效，批次允许部分完成；用户导入则采用整批校验通过后提交。
- 用户导入仅创建，不更新已有账号；新账号默认启用。
- 标签相似为软提醒，同分类精确重名为硬阻断；不做自动合并标签。
- 原型中的既有正式内容不强制全部重新核对；尚未归档的批次执行新流程。

后续进入研发说明前需要定下的高影响事项：是否要求独立人员确认、账号导入是否需要批量更新、公众号采集是否纳入同一归档流程、真实标签检索的相似性效果，以及审计数据的正式保留期限。以上事项不影响按本文默认规则先改原型。
