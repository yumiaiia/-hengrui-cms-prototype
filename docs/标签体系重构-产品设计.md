# 标签体系重构 · 产品设计

> 目标：把"写死的派生逻辑"改为可配置规则，并借这次变更把"什么该是标签、什么不该是标签"重新划清。
> 输入：`恒瑞CMS需求说明文档.pdf`（模块六）、`恒瑞CMS平台智能标签体系_v2-1126 - 02_内容标签.csv`、现有原型 `src/taxonomy.ts` / `src/tagResults.ts` / `src/pages/Tags.tsx`。
> 本文只回答"应该长什么样、为什么、怎么迁移"，不含实现代码。

---

## 1. 结论先行

现在的混乱不是因为标签太多，而是**三种性质完全不同的东西共用了一套"一级分类 + 二级标签"结构**：

| 其实是什么 | 现在被当成 | 后果 |
| --- | --- | --- |
| 内容的一个**标注维度**（内容类型、内容主题…） | 一级标签分类 | 维度自己的属性（单值/多值、是否参与 AI、作用域）无处安放，只能挂在一级分类上凑 |
| 内容上的**业务字段**（用户可见范围、推广性质、内容渠道） | 二级标签 + 独立字段（双重表示） | `Version.visibility` 与"可见范围"标签两套真相；渠道干脆没有模型 |
| 标签之间的**推导关系**（内容类型 → 可见范围） | 目标标签上的一个 `deriveFrom` 数组 | 规则不可总览、不可复用、一个规则覆盖多个目标时要配 N 遍、冲突优先级写死在代码里 |

所以重构的主线只有一句：**拆成"维度 / 值 / 规则"三层，并让规则成为一等对象。**

- **维度（Dimension）**：内容的一个可标注切面，带基数、作用域、AI 参与方式、合并策略。
  - 子类 A **分类维度**：值是标签，可运营增删（内容类型、内容主题、产品、疾病领域…）。
  - 子类 B **枚举字段**：值是系统固定枚举，是内容对象上的业务字段（用户可见范围、推广性质、内容渠道）。
- **值（Value）**：维度下的取值。分类维度下叫"标签值"，枚举字段下叫"枚举项"。值只管自己的名称、别名、启停、历史映射，**不再背派生规则**。
- **规则（Rule）**：`触发（维度 + 一组值） → 结果（维度 + 一组值）`，带作用域、优先级、合并方式、启停、命中统计。

这样，"内容类型=临床研究 就派生 可见范围=All三类用户"这句话，从"写在临床研究这个标签身上"变成"一条可配置规则"，而"All三类用户"也回归它的本来身份——**可见范围字段的一个受众集合**，不再是标签。

## 2. 现状诊断

### 2.1 CSV 已经把答案写出来了，只是被排版成了列

`02_内容标签.csv` 的表头是：`二级字段` 下面挂 **内容类型 / 内容形式 / 内容主题 / 推广性质** 四个字段，每个字段各带一段"判断口径"；而 `用户可见范围`、`内容渠道` 是**跟在内容类型后面的两列**。

也就是说，这张表其实是**一张横向摆放的规则表**：

```
内容类型 = 临床研究  → 用户可见范围 = 已注册待认证、已认证、未注册 ；内容渠道 = （空）
内容类型 = 产品准入  → 用户可见范围 = 已注册待认证、已认证       ；内容渠道 = 企业微信
```

现在需求要"规则可配置"，本质上就是**把这两列立起来，变成第一等的规则对象**。这是个很自然的收口，不需要发明新东西。

同时 CSV 也证明了"不是啥都是标签"：

- `推广性质` 只有"推广 / 非推广"两个值，且口径是"依据宣传目的与审批要求判断"——这是**合规判定字段**，不是标签。
- `用户可见范围` 是三个受众的分档——这是**字段**，还带权限语义。
- `内容渠道` 是发布去向（企业微信 / 网站…），是**发布模块的关联字段**，混进标签库只会让筛选和统计失真。
- 四个字段各有各的"判断口径"，说明它们**不是同一层级的东西并列**，而是"维度"这一层缺失了：维度需要带口径说明、基数、是否互斥。

### 2.2 原型里的具体问题（代码级）

| 位置 | 问题 |
| --- | --- |
| `Tag.deriveFrom` | 规则挂在**目标值**上，只能表达"我由谁派生"。一个规则要多目标就配 N 遍；无法表达目标为字段、优先级、作用域、启停 |
| `taxonomy.aiEligibleTag` | `!tag.manualOnly && !tag.deriveFrom?.length` —— "是否写死"和"是否参与 AI"两个正交维度被硬编码成一个"或"，无法分别配置 |
| `Tag.singleValue` | 基数挂在**一级分类**上，实际是维度属性；连带 `enforceSingleValue` 的择一算法是"人工优先 + 名字更长优先"（`bindingRank`），不可解释、不可配置 |
| `tagResults.applyDerivedTags` | 派生结果 `origin` 写成 `"人工"`，审计里分不清"规则给的"和"人选的第 3 种来源"缺失 |
| `tagResults.exclusionMatches` | 排除记忆按**名称 + 分类 ID** 匹配，标签改名后旧排除记录失配，被人工删掉的派生值可能"复活" |
| `tagResults.deriveVisibility` | "多档命中取最宽"靠 `VISIBILITY_VALUES` 的**数组顺序**硬编码，调档位要改代码 |
| `Version.visibility` + 派生标签 | 同一个业务事实两套存储：字段一份、绑定一份，且 `visibilityManual` 只是一个布尔，撑不住"人工只改了一部分受众" |
| `referenceTags.ts` | 仍是旧的 6 个分类（含"内容主题"8 值），与新 CSV 的 内容类型 23 值 / 内容主题 20 值 完全不对齐 |

### 2.3 需求文档需要同步修订的地方

`恒瑞CMS需求说明文档.pdf` 模块六 6.3(1)(2) 目前写的是"两个预置集合按标签 ID 系统预置固化、界面与 Excel 均不开放编辑"，6.3(2) 还附了一张**固定的**"内容类型 → 可见范围"映射表。本次变更后：

- "两个预置集合"整段取消：**标签库里不再存在"系统预置、不可编辑"的标签或值**，改为"初始数据 + 权限分层 + 引用完整性"（见 3.6）；
- 固定映射表改为**初始规则集**（上线时灌入一次，之后完全由业务维护，可改可删）；
- 6.1 功能目标、6.3(2)1 的"材料级自动派生通用机制"要改为"通用规则引擎"口径。

## 3. 目标模型

### 3.1 三层结构

```
维度 Dimension ──┬── 分类维度（值可运营增删）── 值 Value
                 └── 枚举字段（值可配置，默认预置）── 枚举项 Value
                          ▲                     │
                          │                     │
                     规则 Rule ─── 触发(维度+值集) ─┘→ 结果(维度+值集)
                          │
              内容 Content ── 取值 Binding（dimensionId + valueId + page + origin）
```

三个关键判断：

1. **维度是"内容有什么可标"的定义，值是"能标什么"，规则是"自动怎么标"。** 三者分表存储、分页管理。
2. **内容侧只存"取值"，不存"标签 vs 字段"的区别。** 可见范围也是取值，只是它的维度是枚举字段、合并策略是并集。读取时用 `visibleAudiences(version)` 这样的选择器，避免双写。
3. **规则只引用 ID，不引用名称。** 改名、别名、迁移都不破坏规则。

### 3.2 维度属性（回答"AI 打一个枚举还是允许多值"）

基数、AI 参与、作用域都不是"标签"的属性，而是"维度"的属性——原来这些被塞在 `Tag.singleValue` / `manualOnly` 上，是所有别扭的源头。

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| `kind` | 分类维度 / 枚举字段 | 决定值能不能增删、是否出现在"标签库" |
| `cardinality` | 单值 / 多值（可设上限） | 单值 = 同一位置只允许 1 个值，多值 = 1..N |
| `scope` | 材料级 / 页级 / 两者 | 页级仅对可分页文件（PDF/PPT/Word）生效 |
| `ai` | 闭集参与 / 开放参与 / 不参与 | 闭集 = 模型只能从给定值里选；开放 = 可输出新词进"推荐标签"；不参与 = 只人工/规则 |
| `merge` | 并集 / 优先级 | 多来源（AI + 规则 + 人工）结果如何合并。**属于维度，不属于规则** |
| `fallback` | 兜底值 | 所有规则都不命中时落的值（可见范围 = 最保守档） |
| `humanEditable` | 允许 / 禁止 | 人工能否改规则结果；允许时人工值永远优先于规则 |
| `required` | 无 / 归档必填 | 本期全部为"无"（沿用已定口径） |
| `order` | 值顺序 | 枚举字段的档位顺序（如可见范围由宽到窄） |
| `visibleInDetail` / `filterable` / `exportable` | 布尔 | 决定详情页展示、列表筛选、资产包导出范围 |

值的属性只保留：`名称 / 别名 / 上级值 / 启停 / 排序 / 仅由规则产生`。
**`deriveFrom` 从值上彻底移除**，这是本次变更的核心动作。
**`locked`（系统预置不可编辑）也一并移除**——所有值一视同仁可改，差别只在"谁能改、改了会不会打断引用"。

### 3.3 规则对象

```ts
interface Rule {
  id: string;
  name: string;                 // "内容类型 → 可见范围"
  enabled: boolean;

  trigger: {
    dimensionId: string;
    valueIds: string[];         // 一组触发值，避免一个值配一条
    match: "any" | "all";       // 任一命中 / 全部命中（触发统一为整份并集，不分页）
  };

  action: {
    dimensionId: string;
    valueIds: string[];         // 结果可以是多个（如 已注册待认证 + 已认证）
  };

  priority: number;             // 目标维度为"优先级合并"时用于择一
  createdAt, updatedAt, updatedBy;
}
```

规则**只管"触发 → 结果"和优先级**。合并方式（并集/优先级）、人工能否覆盖、兜底值都在目标维度上定义——同一条字段上可能有多条规则，如果每条规则自带合并策略，就会出现"这条说取并集、那条说取优先级"的互相矛盾，无法解释结果。

设计要点：

- **一条规则可覆盖一组触发值**：CSV 里 9 个内容类型都派生"All三类用户"，现在只需 1 条规则，而不是 9 个标签各配一次。
- **结果是一组值，不是一个值**：可见范围天然是集合（三个受众），这样"多档命中取最宽"不需要特判，维度上的 `merge=并集` 就是最宽。
- **规则有优先级**：单值目标（如推广性质）冲突时按优先级择一，而不是"名字更长"。
- **不区分预置与自建**：规则一律可改、可停用、可删；上线只灌一次初始数据，之后以业务维护为准。
- **人工优先是全局不变量，不是每个规则的开关**：人工值 > 规则 > AI。规则与人工冲突时不覆盖，只在详情页给一条"规则建议：已认证"的提示卡，让人决定；能不能改由目标维度的 `humanEditable` 决定。

### 3.4 取值来源统一为三种

```
origin: "AI" | "人工" | "规则"     // 规则附带 ruleId
```

派生不再伪装成"人工"。带来的好处：详情页能给"由规则「内容类型 → 可见范围」派生"的角标；审计能回答"这条可见范围是谁给的"；统计能算规则命中率与人工纠正率。

### 3.5 合并与重算顺序（必须写死，否则行为不可预测）

每次绑定/解绑/重新匹配后，按固定顺序重算：

1. **AI 匹配**：只处理 `ai != 不参与` 且非 `仅由规则产生` 的值，闭集维度只允许返回集合内的值。
2. **规则推导**：触发集合 = 整份（材料级 ∪ 全部页级）已绑定值的并集；按规则优先级依次求值。
3. **合并**：按**目标维度**的 `merge` 取并集，或按优先级取一条（不是按规则各说各的）。
4. **人工锁定**：人工设过的位置不被规则覆盖（目标维度 `humanEditable=允许` 时人工永远优先），但冲突要留痕，用于"人工与规则不一致"的报表。
5. **单值收敛**：单值维度仍多于 1 个 → 不静默丢弃，标记"待人工确认"。
6. **排除记忆**：按 `dimensionId + valueId + page` 记录，命中则跳过该值。

> 与现状差异：现在是"派生 → 单值抢位"，没有优先级概念；改后是"优先级 → 合并 → 人工锁定"，可解释。

### 3.6 没有"系统预置不可编辑"之后，靠什么兜底

既然全做成配置项，就不该再留"某些标签技术上改不了"。原来"写死"承担的作用（合规不被误改、统计口径不漂、规则不被打断）拆给四个机制，全部是**约束**而非**锁死**：

| 机制 | 解决什么 | 怎么落地 |
| --- | --- | --- |
| 权限分层 | 谁能改什么 | 维护维度与值（标签管理员）、编辑规则（规则管理员）、给内容打标（业务员）三个权限分开；没有权限的人看到的是只读，不是"系统锁定" |
| 写入留痕 | 改动可追溯即可，不靠"锁" | 值的增、改、停用，规则的增、改、删，全部写审计（谁、何时、改了什么、影响多少内容）；出问题回查，而不是禁止操作 |
| 引用完整性 | 改值不能把规则打断 | 被规则或内容引用的值不允许硬删，只能停用；停用时列受影响规则与内容数，规则转"待修复"状态并提示，不静默失效 |
| 关键字段不变量 | 合规底线 | 可见范围必须恒有值：所有规则都不命中时落"最保守档"；发布前校验为空则阻断。这是校验，不是硬编码映射 |

还有一条边界要说清：**真正"业务不可改"的只剩枚举字段的枚举项**——未注册 / 已注册待认证 / 已认证、推广 / 非推广、几个发布渠道。它们不是标签，而是内容 schema 的一部分，权限与合规判定直接依赖这些值，要改只能产品改版本。这条边界正好回答"是不是啥都是标签"：标签可以配到底，字段定义留在产品侧。

CSV 里"恒瑞现有标签（全量对应）"那一列只是历史对照，**不进模型**：迁移时用它把旧绑定对到新取值，对完即弃，界面上不再出现"历史旧名"。

## 4. 标签体系重排（按 CSV 落地）

### 4.1 十个维度各归其位

| # | 维度 | 类型 | 基数 | 作用域 | AI | 值域 | 归属 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 内容类型 | 分类维度 | 单值 | 材料 | 闭集参与 | 23 | 标签体系 |
| 2 | 内容形式 | 分类维度 | 单值 | 材料 | 闭集参与（可先按文件类型预填） | 8 | 标签体系 |
| 3 | 内容主题 | 分类维度（开放） | 多值 | 材料 + 页 | 开放参与 | 20 + 子主题 | 标签体系 |
| 4 | 产品 | 分类维度 | 单值（可配多值上限） | 材料 | 闭集参与 | 36 | 标签体系 |
| 5 | 疾病领域 | 分类维度 | 多值 | 材料 | 闭集参与 | 70 | 标签体系 |
| 6 | 药物分类 | 分类维度 | 多值 | 材料 | 闭集参与 | 37 | 标签体系 |
| 7 | 治疗方案 | 分类维度 | 多值 | 材料 | 闭集参与 | 28 | 标签体系 |
| 8 | 推广性质 | 枚举字段 | 单值 | 材料 | 不参与 | 2 | 内容字段 |
| 9 | 用户可见范围 | 枚举字段（受众集合） | 集合 | 材料 | 不参与 | 3 受众 | 内容字段 |
| 10 | 内容渠道 | 关联字段 | 多值 | 材料 | 不参与 | 4 平台 | 发布模块 |

要点：

- **1–7 才是可打标的"标签体系"**；8–10 是内容字段，在「维度与值」的字段分组里维护，但不出现在打标选择器里（AI 不参与、人工按字段维护）。字段可新增，新增时即为枚举字段。
- 所有取值（含字段枚举）都**可配置**：能改名、调序、停用、新增；差别只在"被谁引用"——被规则、内容或权限判定引用时，不提供直接删除，只允许停用，避免悬空与误判。统计口径靠审计 + 使用次数看住，不靠"锁死"。
- 内容主题 / 疾病领域是**开放值**：允许 AI 输出新词进"推荐标签"，人工采纳后才入库——这正好复用现有推荐标签链路。
- `产品` 建议单值：一份材料通常一个主推产品；确需多产品时按"单值 + 例外标记"处理，比默认多值更利于统计。

### 4.2 可见范围改用"受众集合"

不要把可见范围做成 `"All三类用户" | "已注册待认证" | "已认证"` 三选一，而是三个受众的集合：

```
受众 = { 未注册, 已注册待认证, 已认证 }
All三类用户        = {未注册, 已注册待认证, 已认证}
已注册待认证、已认证 = {已注册待认证, 已认证}
```

好处：

- "多档命中取最宽"不再需要特判，并集天然最宽；
- 人工可以精细调整（比如在 All 基础上去掉"未注册"），而不是只能整体覆盖；
- 档位顺序放进维度 `order` 配置，调档位不用改代码；
- 与"未注册用户看不到专业内容"的权限语义对得上。

### 4.3 内容渠道归位

CSV 里"内容渠道 = 企业微信"只出现在产品准入、FAQ、产品 DA、科室会幻灯、学术会议幻灯这几类。这本质是**"这类内容默认投放到企业微信"的默认建议**，不是内容属性。建议：

- 渠道作为发布模块的多值字段；
- 标签体系里只保留一条可选规则"内容类型 → 默认渠道建议"，结果为**建议**而非强制，发布时预填、可改。

## 5. 管理界面

「标签管理」改名为「标签与规则」，**只保留两个页签**。不按"标签 / 字段 / 派生字段"分页面——那是按对象种类切，会切出三套入口，同一件事改两处。按"定义"和"关系"切，才是两个页面。

### 5.1 页签一：维度与值（定义）

- 左侧：维度列表，分两组——**分类维度**（内容类型 / 内容主题 / 产品…）与**枚举字段**（可见范围 / 推广性质 / 渠道）。每行显示 `基数 / AI / 作用域` 角标。
- 右侧：值表格，列 = 名称 / 别名 / 状态 / 被引用文件数 / 操作。字段与分类维度的取值同样可新增、改名、停用；不提供直接删除。
- 选中枚举字段时，右侧多一块**字段设置**（就是该维度自己的属性）：`fallback` 兜底档、`humanEditable`、合并策略。**不另开页面**，因为这些本来就是维度属性，跟"这个维度叫什么、有几个值"是同一层信息。
- 值的编辑弹窗只剩：名称、别名、上级值、启停、排序、是否仅由规则产生。**没有派生规则字段。**
- 字段设置里只显示"被 N 条规则引用（只读）+ 跳转规则页"，不做规则编辑，避免两个入口改同一件事。

### 5.2 页签二：派生规则（关系）

- **所有派生关系都在这一个列表里**，不按字段分页、不给每个字段做一个规则页。无论目标是标签值还是枚举字段，规则长得一样。
- 规则列表：规则名 / 触发 → 结果（一句话可读，如 `内容类型 ∈ {临床研究, 文献解读…} → 可见范围 = All三类用户`）/ 优先级 / 状态 / 操作。不展示来源徽标、单条影响数与"待重算"状态：保存规则即重算。
- 新建规则向导四步：
  1. 选触发维度与值（支持"任一 / 全部"）；
  2. 选目标维度与结果值（可多选）；
  3. 优先级（仅在"优先级合并"的目标维度上才有意义；并集类字段该步自动跳过）；
  4. **试算**：输入一份已有内容或手动勾选几个值 → 预览派生结果，确认后保存。
- 改规则时给**影响面提示**：「该规则当前影响 128 份内容；存量内容不会自动重算，将在下次"同步最新标签到文件"或重新打标时生效」。与现有链路一致，不偷偷改历史版本。
- 规则不再区分预置与自建；初始数据只在上线时灌一次，之后以业务维护为准。
- 值被规则引用时不允许硬删，只允许停用；停用前弹出受影响规则与内容数，规则转"待修复"并提示。

### 5.3 内容详情页

- 标签区按**维度分组**展示（内容类型 / 内容主题 / 疾病领域…），不再按"一级分类"。
- 规则派生值用灰底 chip + "规则"角标，hover 显示规则名；人工值用实底；AI 值用浅色。
- 单值维度冲突时给一条提示条：「规则建议：已认证（当前人工设为 All三类用户）」+ 两个按钮"采用 / 保持"。
- 派生值被人工删除 → 记排除记忆（按 ID），并显示"已排除规则派生，重新添加可恢复"。

### 5.4 Excel 导入导出

从双 sheet 改为三 sheet：

| sheet | 列 |
| --- | --- |
| 维度 | 维度名 / 类型 / 基数 / 作用域 / AI / 合并策略 / 填充方式 / 兜底值 / 人工可改 / 顺序 |
| 值 | 维度名 / 值 / 别名 / 启停 / 排序 |
| 规则 | 规则名 / 触发维度 / 触发值（分号分隔）/ 匹配方式 / 目标维度 / 结果值 / 优先级 / 启停 |

导入时规则行若引用了不存在的维度或值，整行报错并跳过（沿用现有"逐行处理 + 错误列"的口径）。

## 6. 迁移方案

### 6.1 数据映射

| 现状 | 目标 |
| --- | --- |
| 一级分类 → 二级标签 | 分类维度 → 值（分类名保留，基数从 `singleValue` 迁到维度属性） |
| 目标标签的 `deriveFrom: [id…]` | 反向聚合为规则：`触发 = deriveFrom 集合 → 结果 = 该标签`；同一 `deriveFrom` 集合被多个目标共用时合并为一条多结果规则 |
| `state.visibilityRules` | 转为枚举字段"用户可见范围"的规则，`visibility` 值展开为受众集合 |
| `Version.visibility` | 转为"用户可见范围"维度的取值（`origin: 人工` 或 `规则`，按 `visibilityManual` 判定） |
| `TagExclusion { name, parentId, page }` | 改为 `{ valueId, page }`；迁移时按名称查一次 ID，查不到则丢弃并记迁移日志 |
| `manualOnly` / `deriveFrom` 对 AI 的排除 | 迁到维度 `ai` + 值 `仅由规则产生` 两个属性 |
| `Tag.locked`（系统预置不可编辑） | 删除该属性；原"预置"标签降级为普通值，"预置"身份只在初始化灌数据时用一次 |

### 6.2 兼容与回滚

- 旧数据迁移一次性完成，`schema` 升到 3；迁移后保留只读快照，便于回滚。
- 迁移期间不重算任何已归档内容，只把"当前值"翻译成新结构，规则只在下次绑定/匹配/同步时生效。

## 9. 一句话总结

**把"标签"这个词收窄到"分类维度的取值"，把可见范围/推广性质/渠道还原成字段，把派生关系提升为可配置规则。** 这样"临床研究 → All三类用户"不再是一段写死的 if，而是一条能被业务打开、修改、试算、停用的规则；标签改名、增删、迁移都不再牵动规则。既然都做成配置项，也就没有"系统预置不可编辑"的标签了——剩下的约束交给权限、治理、引用完整性和关键字段校验，交不到"技术上锁死"。

## 10. P0 落地情况（原型）

### 10.1 已实现

| 层 | 落地内容 |
| --- | --- |
| 数据模型 | 标签树的根节点就是「维度」，`kind / cardinality / scope / ai / merge / fallbackId / humanEditable`；取值 `derivedOnly / order`；**删除 `locked / manualOnly / deriveFrom / singleValue / legacyNames / valuePolicy / fillMode`** |
| 规则 | `State.rules` 独立存储，`触发（维度 + 一组取值 + 任一/全部）→ 结果（维度 + 一组取值）`，带优先级与启停；`applyRules` 幂等重算，规则产物 `origin="规则"` 且带 `ruleId` |
| 字段 | `Version.fields`（维度 ID → 取值 ID 集合）+ `fieldsManual`；用户可见范围 = 三个受众的集合，支持兜底档；旧 `visibility / visibilityRules` 迁移后删除 |
| 排除记忆 | 优先按 `valueId` 记录（改名安全）；尚未入字典的推荐词回退「名称 + 维度」，保留取消推荐的能力 |
| 单值收敛 | 人工 > 规则 > AI，同级保留先到的；去掉「名称更长」的隐式偏好 |
| 界面 | 「标签与规则」= 维度与值 / 派生规则 / 推荐标签；规则向导含触发-结果-优先级-试算；详情页受众复选、规则建议、恢复按规则；内容库列表用短标签 |
| 迁移 | `workspaceRevision` 升到 10：旧演示分类合并进同名新维度、无绑定的旧取值清理、旧触发配置转规则、补齐 3 条 CSV 预置规则；旧演示标签 t1~t11 改写为 CSV 取值 |
| 测试 | 173 条通过；`tagAttributes` 全量重写为 24 条，覆盖别名、单值、受众并集、兜底、人工覆盖、规则产物撤销、排除记忆、旧数据迁移、Excel 往返 |

### 10.2 尚未做（P1 / P2）

- 规则影响面提示（「当前影响 N 份内容」）；当前改为保存即重算，不再展示影响数。
- Excel 仍是双表（标签分类 / 标签），未拆维度 / 值 / 规则三表。
- 字段取值与权限侧的联动只做了提示，未做校验（新增受众档位时不会检查权限配置）。
- 枚举字段的档位顺序（`order`）与推广性质、内容渠道尚未在内容侧露出；渠道仍待归位发布模块。
- 规则与人工冲突只在详情页文案提示「规则建议 X」，未做一键采用/保持的操作按钮。

> 验收路径：标签管理 → 维度与值（看 10 个维度、字段取值可编辑）→ 派生规则（3 条预置规则、可试算）→ 内容详情 → 编辑标签（三个受众复选、取消一个后变「人工设置」、可恢复按规则）→ 内容库列表可见范围显示「全部用户 / 注册+认证 / 仅认证」。注：可见范围的取值个数与名称完全由字段配置决定，列表文案随之变化。

## 11. P1 / P2 落地与跨模块影响

### 11.1 P1：规则的影响面与重算

| 能力 | 落地 |
| --- | --- |
| 影响面 | 保存规则/导入时在后台统计命中份数（用于提示与审计），界面不常驻展示单条影响数 |
| 生效 | 保存/停用/删除规则后立即重算正式内容当前版本（幂等），不维护"待重算"状态 |
| 重算入口 | 统计条上的「重算」与规则页「重算受影响内容」；只重算规则产物，人工改过的字段与绑定不动 |
| 生效口径 | 保存规则不等于生效：先提示影响面，再显式重算；重算走审计（`重算规则结果` + 影响份数） |
| 撤销 | 停用规则后重算，规则产物自动消失；人工值保留 |

### 11.2 P2：三维度交换与属性配置

| 能力 | 落地 |
| --- | --- |
| Excel 三表 | 「维度 / 取值 / 规则」三张表，可整包导出、改完导回；表头校验、逐行错误、相似检查沿用 |
| 规则往返 | 规则按名称引用维度与取值，导入时校验存在性；同批新建的取值可被后续规则引用 |
| 兜底值 | 支持兜底值写在后面的「取值」表里（整轮处理完再解析），不再要求先建值再建维度 |
| 维度属性 | 类型、基数、作用域、AI 匹配、合并策略、填充方式、兜底值、人工可改、顺序均可配置并随 Excel 往返 |
| AI 约束 | 三态落到匹配链路：`不参与` 完全不进 AI；`仅规则产生` 的值 AI 直接跳过；`闭集` 只从给定值里命中。`开放` 的"新词进推荐"依赖模型接入，原型只保留口径 |
| 兼容性 | 旧的两张表模板不再被接受（会提示缺少工作表），需要重新下载模板——这是本次唯一的破坏性变更 |
