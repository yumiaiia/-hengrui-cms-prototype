## 2. 需求文档修改点（`恒瑞CMS需求说明文档-3.md`）

按 `需求修订-标签体系v3-最终.md` 执行（已含整章替换稿与边界场景），其要点是：

1. **模块六 6.3(1)**：维度新增"禁止停用"——删掉维度编辑器里的启用开关；维度表去掉"启用"列；整维度下线只能逐个停用取值。
2. **模块六 6.3(2)**：
   - 删 `scope`（触发统一为"整份并集"）；
   - 删 `source`（来源仅审计、界面不展示，最终口径是不再区分来源）；
   - 优先级必填 + 同目标维度唯一；
   - "生效方式"改为：**保存/停用/删除规则时立即重算正式内容当前版本**，不再有"待重算"状态。
3. **模块六 6.3(3)** 用户可见范围：明确"它只是值、不控制任何权限"；兜底保留 `已认证`。
4. **模块六 6.3(4)** 加一句：**停用取值仍可作规则触发**（判断依据是内容上的绑定是否存在）。
5. **模块六 6.3(5)** Excel：维度表去掉"启用""填充方式"两列；规则表去掉"来源"列；导入时"维度类型与库内不一致"报错。
6. **模块六 6.3(7) 字段规则表**：删"填充方式"行；"优先级"改"必填、同目标维度唯一"。
7. **模块六 6.3(6)** 补"批次冻结规则快照"：发起时复制规则快照，批次内一致，之后规则改动不影响本批。
8. **模块四 4.3 字段表**、**模块五 5.3**：来源枚举保留 `AI / 人工 / 规则`；字段交互口径统一为"人工标记、可恢复按规则、排除记忆仅用于标签与推荐"。

## 3. 原型代码修改点

### 3.1 模型 `src/model.ts`
- `Tag`：删除 `fillMode`；维度 `enabled` 保留但界面不再提供停用（恒 true）。
- `Rule`：删除 `source`、删除 `trigger.scope`；`trigger` 只保留 `dimensionId / valueIds / match`；`priority` 保留。

### 3.2 字典 `src/referenceTags.ts`
- 维度 spec 删除 `fillMode`；`referenceRules` 删除 `source` 与 `scope`。

### 3.3 规则引擎 `src/tagResults.ts`
- `ruleMatches` 删除 `scope` 分支，统一 `triggerSet` 整份并集。
- `enforceSingleValue`：单值冲突排序改为 `order` 升序，order 相同按名称升序（替代"先到优先"）。
- `tagDefinitions` 快照去掉 `source / scope / fillMode` 相关字段。

### 3.4 匹配与冻结 `src/tagMatching.ts`
- `startTagMatching`：批次增加 `ruleSnapshot`（`structuredClone(s.rules)`）。
- `advanceTagMatching`：用 `batch.ruleSnapshot` 计算，不再读实时 `s.rules`。

### 3.5 规则影响 `src/ruleImpact.ts`
- 删除 `pendingRecalc`；保留 `recalcRules(state)`（全量当前版本）。
- 保存/停用/删除规则后统一调用 `recalcRules`。

### 3.6 页面 `src/pages/Tags.tsx`
- 维度编辑器：去掉"启用"勾选；新增维度默认 `enabled: true`；删除 `fillMode` 相关默认值。
- 规则编辑器：删除 `scope`/`source`；优先级必填，保存时校验同目标维度不重复（重复弹提示）。
- 规则列表：删除"来源""影响 N 份""待重算"与"重算受影响内容"按钮；保留优先级、状态、操作、"结果部分不可用"。
- 保存/停用/删除规则后立即 `recalcRules` 并 Toast"已重算 N 份内容"。

### 3.7 导入导出 `src/tagTransfer.ts`
- 维度表头：`ID / 维度名称 / 类型 / 基数 / 作用域 / AI 匹配 / 合并策略 / 兜底值 / 允许人工修改`（去掉"填充方式、启用、对外展示"）。
- 规则表头：`ID / 规则名称 / 触发维度 / 触发取值 / 匹配方式 / 目标维度 / 结果取值 / 优先级 / 启用`（去掉"来源"，无 scope）。
- 校验新增：① 维度类型与库内不一致 → 该行报错；② 同一目标维度优先级重复 → 报错。

### 3.8 迁移 `src/workflow.ts`
- 迁移清洗：删除旧数据里的 `fillMode / source / scope`（含取值/维度/规则）。
- 旧 `visibilityRules` 转规则时不再写 `source / scope`。
- 维度 `enabled` 若为 `false` → 强制 `true`（维度禁止停用）。

### 3.9 测试
- 更新 `rules.test.ts`、`tagAttributes.test.ts`：规则 fixture 去 `source/scope`；删除 `pendingRecalc` 相关用例，改为"保存即重算"；新增"优先级唯一校验""导入改类型报错""单值按 order 冲突""批次冻结快照"用例。

## 4. 边界场景最终口径

| 场景 | 最终行为 |
| --- | --- |
| 停用维度 | 不允许（维度恒启用） |
| 停用取值（作触发） | 仍命中（按绑定存在判断） |
| 停用取值（作结果） | 不产出；规则行标"结果部分不可用" |
| 规则多命中（并集字段） | 取并集 |
| 规则多命中（优先级字段） | 取优先级最小的一条；优先级唯一故无并列 |
| 规则与人工冲突 | 人工优先，界面给"规则建议 X"，可恢复按规则 |
| 规则触发范围 | 只有"整份并集"，无页级 |
| 保存/停用/删除规则 | 立即重算当前版本，Toast 报份数 |
| 批次进行中改规则 | 不影响本批（冻结快照），新批次生效 |
| 单值维度 AI 多命中 | 保留 order 最小，相同按名称 |
| 可见范围 | 普通值、不控权限、兜底"已认证" |
| 字段人工改动 | 走人工标记，可恢复按规则；排除记忆仅用于标签与推荐 |
| 推荐采纳 | 落推荐自带维度；单值维度冲突替换原值并记排除 |
| 导入 | 禁改维度类型；优先级唯一；规则引用校验；旧模板拒绝 |
